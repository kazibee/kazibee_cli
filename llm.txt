# Kazibee CLI — guide for agents authoring extensions

The `kazibee` CLI only validates extension packages and prints guidance. It does not
install, run, configure, compile, or publish extensions; the Kazibee desktop app does that
(Settings → Tools), and its chat models call extensions through `list_extensions`,
`describe_extension`, and `code_sandbox`.

## Commands

- `kazibee validate [path]` — validate the package exactly as the desktop app will. Read-only.
  Prints the content digest the app will compute. Exits non-zero on errors. `--json` for
  machine-readable output.
- `kazibee spec [package|guide]` — print the full package contract, or this guide.

## Package rules

- Entry: `main` in package.json (default `./src/index.ts`) must `export default function main(env)`
  returning an object of methods. Annotate every method's return type
  (e.g. `async (id: string): Promise<Note>`); inferred types from uninstalled SDKs become `any`
  in the API the model reads.
- `kazibee.id` (default: package name) must be lowercase kebab-case.
- `kazibee.brief`: one line telling the model when to use the extension. `kazibee.tags`: a few
  kebab-case terms.
- `llm.txt`: usage manual returned by `describe_extension`.
- `permissions.json`: `net` hosts (no `*`), `env` keys the user sets in Settings, and
  `methods` (`{ "list": { "write": false } }` keeps a method available in read-only mode).
- Do not commit `.kazibee/`, generated `.d.ts` bundles, or seals. The app generates the
  TypeScript API itself when the package is installed or linked, and caches it.

## Shipping

Push the repository to GitHub. Users install it in the desktop app with `github:owner/repo`
(or a github.com URL); the app records the commit it installed. Other git hosts and npm are
not install sources, and there is no publishing step.
